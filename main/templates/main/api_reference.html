Quick start

Every endpoint lives under {{ api_base }} and speaks JSON. Log in once with your Jolof username and password to get a session token, then send the token with each request. Your role currently gives you:

  • Recipes and tags: {% if can_api_recipes %}yes{% else %}no{% endif %}
  • Meal planner, workspace and freezer: {% if can_api_mealplan %}yes{% else %}no{% endif %}
1. Log in and keep the token
TOKEN=$(curl -s -X POST {{ api_base }}auth/login/ \
  -H 'Content-Type: application/json' \
  -d '{"username": "{{ user.username }}", "password": "YOUR-PASSWORD", "client_name": "my-script"}' \
  | jq -r .token)
2. Use it
curl -s '{{ api_base }}recipes/?view=names&q=chicken' \
  -H "Authorization: Bearer $TOKEN"
3. Log out when you're done
curl -s -X POST {{ api_base }}auth/logout/ -H "Authorization: Bearer $TOKEN"

The examples use curl and jq, but any HTTP client works.

Session tokens

Log in
POST/api/v1/auth/login/

Send username and password, and optionally a client_name that labels the session on your Profile page (for example jolof-mcp). The answer is 201 with the token. It's shown only this once, so keep it.

Response
{% verbatim %}
{
  "token": "jlf_oBWx3k...",
  "token_prefix": "jlf_oBWx",
  "user": {"id": 3, "username": "me"},
  "permissions": ["api-mealplan-read", "api-recipe-read"],
  "client_name": "my-script",
  "created_at": "2026-10-24T15:00:00Z",
  "last_used_at": "2026-10-24T15:00:00Z",
  "idle_timeout_minutes": 60,
  "expires_at": "2026-10-24T16:00:00Z"
}
{% endverbatim %}

Login is refused with one of these:

StatusCodeMeaning
400invalid_credentialsWrong username or password, or the account is deactivated.
403no_api_accessThe role has no API permission.
403password_change_requiredLog in to Jolof in a browser and change the password first.
429throttledMore than 10 attempts a minute for this username.
Send the token

Add this header to every other request:

Authorization: Bearer jlf_oBWx3k...

A token lasts the whole session, however long that is, as long as it keeps being used. It stops working when:

  • it goes unused for the idle timeout ({% if idle_timeout_minutes %}currently {{ idle_timeout_minutes }} minute{{ idle_timeout_minutes|pluralize }}{% else %}currently off{% endif %}). Every request resets the clock;
  • your password changes;
  • you log out, or the session is revoked from your Profile (or by an administrator);
  • your account is deactivated.

Any of these answers 401 with code session_expired or invalid_token. Just log in again. Your role is checked on every request, so a role change applies straight away.

Check the session
GET/api/v1/auth/session/

The same details as the login response, without the token. expires_at is when the session ends if it goes unused; each request pushes it back. It's null when there's no idle timeout.

Log out
POST/api/v1/auth/logout/

Ends the session for the token sent. Answers 204 with no body.

Responses & errors

Every error has the same shape. fields appears when a parameter was wrong, and says which:

{% verbatim %}
{
  "error": {
    "code": "invalid",
    "message": "Must be one of: names, summary, full.",
    "fields": {"view": ["Must be one of: names, summary, full."]}
  }
}
{% endverbatim %}
StatusTypical codeMeaning
400invalidA bad parameter.
401not_authenticated, invalid_token, session_expiredNo token, a bad one, or one that has stopped working. Log in again.
403permission_deniedYour role doesn't include this endpoint.
404not_foundNo such recipe, or a page past the end.
429throttledToo many login attempts.

Recipes

Needs the api-recipe-read permission.

GET/api/v1/recipes/

Search, filter, sort and page through recipes. Every parameter is optional, and they combine with AND.

Response sizes: view

The main lever for keeping responses small. Each size includes everything in the one above it.

viewFieldsMax page size
namesid, name500
summary (default) adds slug, description, rating, complexity, effort, health, gluten_free, dairy_free, vegetarian, vegan, tags, is_favorite, is_public100
full adds ingredients, instructions, notes, source_url, image_url, web_url, created_at, updated_at100
  • Ratings (rating, complexity, effort, health) are 1 to 5, or null when unrated.
  • Dietary flags are always true or false.
  • tags are "label:value" strings, like "cuisine:thai".
  • is_favorite is about your favorites.
  • image_url is a signed link that stops working after about an hour; web_url is the recipe's page in Jolof.
Filters
ParameterExampleKeeps
qq=chicken rice Searches like the Recipes page: every word must appear in the name, ingredients, description or a tag. A label:value word (or just label:) matches tags.
tagtag=cuisine:thai Recipes with exactly that tag (case doesn't matter). Repeat it to require several: tag=cuisine:thai&tag=course:main.
cookedcooked=trueRecipes tagged "cooked".
favoritesfavorites=trueYour favorites.
publicpublic=trueRecipes with a public share link.
vegetarian, vegan,
gluten_free, dairy_free		vegan=trueRecipes with that box ticked.
min_ratingmin_rating=4Rated at least this (1 to 5).
min_healthmin_health=4Healthiness at least this.
max_complexitymax_complexity=2Complexity at most this.
max_effortmax_effort=2Effort at most this.
idsids=3,17,42Just these recipes.

Unrated recipes never pass a rating filter. Not sure which tags exist? Ask tags/.

Sorting: sort

The same choices as the Recipes page. Ties sort by name, and unrated recipes always sort last.

sortOrder
recipe-name (default)A to Z, ignoring case.
recently-addedNewest first.
highest-ratingBest rated first.
most-tagsMost tags first.
complexity-asc / complexity-descSimplest / most complex first.
effort-asc / effort-descLeast / most effort first.
healthiness-asc / healthiness-descLeast / most healthy first.
in-planner-desc / in-planner-ascRecipes in your meal-planner workspace first / last.
favorites-desc / favorites-ascYour favorites first / last.
public-desc / public-ascPublicly shared recipes first / last.
Paging

Use page (from 1) and page_size (default 25, up to 100, or 500 with view=names). A page past the end is a 404. Follow next until it's null to walk every page.

{% verbatim %}
{
  "count": 213,
  "page": 1,
  "page_size": 25,
  "total_pages": 9,
  "next": "https://jolof.example/api/v1/recipes/?page=2",
  "previous": null,
  "results": [ ... ]
}
{% endverbatim %}

Tags

Needs the api-recipe-read permission.

GET/api/v1/tags/

Every tag with how many recipes use it, ordered by label then value: the values worth passing to the recipes tag filter. q matches the label or value. Paged like recipes, 100 a page by default and up to 500.

Meal plan

Needs the api-mealplan-read permission. The meal planner endpoints answer for your household, or for your own planner if you're not in one; household says which (null for your own).

GET/api/v1/meal-plan/

What's planned each day, ordered by date and then slot.

ParameterDefault
start YYYY-MM-DDToday (the server's date, in UTC).
end inclusiveTwo weeks from start. At most 92 days after it.
 
curl -s '{{ api_base }}meal-plan/?start=2026-10-26&end=2026-11-01' -H "Authorization: Bearer $TOKEN"
{% verbatim %}
{
  "household": {"id": 1, "name": "Home"},
  "start": "2026-10-26",
  "end": "2026-11-01",
  "entries": [
    {"id": 51, "date": "2026-10-26", "slot": 1, "name": "Jollof Rice",
     "recipe": {"id": 12, "name": "Jollof Rice", "slug": "jollof-rice"}, "custom_text": ""},
    {"id": 52, "date": "2026-10-27", "slot": 1, "name": "Leftovers",
     "recipe": null, "custom_text": "Leftovers"}
  ]
}
{% endverbatim %}

recipe is null for a custom-text entry, and name is then the text. slot is the entry's position within its day, from 1.

Tips for AI agents

  • Start with view=names: the whole library fits in one small response. Then fetch only the recipes you need with ids=...&view=full or recipes/id/.
  • Use view=summary when choosing between recipes. It has ratings, tags and dietary flags, without the long text.
  • Narrow on the server rather than reading everything: q, tag, the dietary flags and the rating limits all combine.
  • Call tags/ to learn which labels and values exist before filtering on them.
  • Pass a client_name when logging in, so the session is easy to spot and revoke on your Profile page.
  • On a 401, log in again and retry once.
